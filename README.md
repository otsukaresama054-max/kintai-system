# LINE出退勤管理システム(Google Apps Script + LIFF)

LINEのLIFF(LINE内Webページ)から「出勤」「退勤」ボタンで打刻し、
Googleスプレッドシートに記録、打刻の都度メール通知を送るシステムです。

## 1. 全体構成

> **重要**: 画面(LIFF)とデータ処理(GAS)は**別々の場所でホスティング**します。
> Google Apps ScriptのHtmlServiceは、ページを内部で自動的にiframeへ入れて配信する
> 仕様になっており、これがLINEログインの内部処理(`access.line.me` への
> フレーム表示)とぶつかって動作しません(`X-Frame-Options: deny` で拒否される)。
> そのため、画面(`index.html`)は **GitHub Pages** などの静的ホスティングで公開し、
> GASは「打刻データを受け取ってスプレッドシートに記録するAPI」に専念させます。

```
[LINEアプリ]
   │ LIFF URL (liff.line.me/{LIFF_ID}) を開く
   ▼
GitHub Pages で公開した index.html (画面)
   │ 位置情報取得(毎回許可を要求。拒否時は打刻不可)
   │ fetch(POST) でGASの exec URL を呼び出す
   ▼
GAS Web App (doPost / Code.gs)  ※画面は返さず、API専用
      ├─ LiffAuth.gs      … LINEのIDトークンをLINEサーバーで検証
      ├─ Employees.gs     … 社員マスタから正式な氏名を取得
      ├─ Geocoding.gs     … 緯度経度 → 住所(OSM Nominatim。取得できる範囲で最大限詳しく)
      ├─ AttendanceSheet.gs … スプレッドシートへ記録
      └─ Notify.gs        … 通知(現在はメール。差し替え・追加が容易)
```

| `appsscript.json` | Google Apps Script | マニフェスト |

| `Employees.gs` | Google Apps Script | 社員マスタの読み込み |

## 3. 事前準備

### 3.1 スプレッドシートを用意する

1. 新しいGoogleスプレッドシートを作成し、そのIDを控えておく
   (URLの `https://docs.google.com/spreadsheets/d/【ここ】/edit` の部分)。
2. 後述のスクリプトプロパティ `SPREADSHEET_ID` に設定後、スクリプトエディタで
   `setupSheets` 関数を1回実行すると、以下の2シートとヘッダー行が自動生成されます。

**Records シート(出退勤記録)**

| A | B | C | D | E | F | G | H | I | J | K |
|---|---|---|---|---|---|---|---|---|---|---|
| タイムスタンプ | 氏名 | 日付 | 区分 | 時刻 | 緯度 | 経度 | 住所(簡易) | LINE UserID | 備考 | コメント |

> **K列(コメント)は後から追加した列です。** `setupSheets` は既存のシートには
> 手を加えないため、既にお使いのスプレッドシートでは **K1セルに手動で
> 「コメント」と入力**しておいてください(これから新規に作るスプレッドシートは
> 自動でK列まで作成されます)。

**Employees シート(社員マスタ)**

| A | B | C | D | E |
|---|---|---|---|---|
| LINE UserID | 氏名 | 通知先メール(任意) | 有効/無効 | リマインド対象 |

> **E列(リマインド対象)は後から追加した列です。** `setupSheets` は既存の
> シートには手を加えないため、既にお使いのスプレッドシートでは **E1セルに
> 手動で「リマインド対象」と入力**しておいてください(これから新規に作る
> スプレッドシートは自動でE列まで作成されます)。
> この列に **「対象」と入力した人だけ**、9.の始業・終業リマインドが届きます
> (空欄の人には送られません。最初は一部の社員だけ「対象」にしておき、
> 運用を広げるタイミングでE列を埋めていく、という使い方を想定しています)。

> 位置情報の利用を拒否された(または取得失敗した)場合は、実際の出退勤としては
> 記録されませんが、「誰が・いつ・どのボタンで拒否したか」を区分に
> **「出勤(拒否)」「退勤(拒否)」** として同じ `Records` シートに1行残します
> (緯度・経度・住所は空欄、備考欄に拒否/失敗の理由を記録)。
> 集計時はこの「(拒否)」の区分を除外してください。

> `備考`列(J)には、出勤ボタンの下にある「訪問先」、退勤ボタンの下にある
> 「最終訪問先」の入力内容が、それぞれの打刻の行に記録されます
> (未入力なら空欄のまま)。`コメント`列(K)には、出勤・退勤どちらでも
> 使える自由記入の「備考」欄の内容が記録されます。どちらも月次PDFに
> 列として出力されます。

> `Employees` シートには、打刻を許可する人ごとに行を追加してください。
> - **LINE UserID**: 本人が一度LIFFにアクセスしてエラーになった際、
>   `Records` シートや実行ログに出力される値を控えて転記するか、
>   LINE公式アカウントの友だち一覧(Messaging API)から確認してください。
> - **有効/無効**: 「有効」という文字列でないと打刻できません(退職者の無効化などに利用)。

### 3.2 GASをWebアプリとしてデプロイする(データ処理API側)

先にこちらを済ませておくと、後述のLIFF設定でエンドポイントURLがすぐ用意できます。

1. Apps Scriptエディタで [デプロイ] > [新しいデプロイ] を選択
2. 種類: 「ウェブアプリ」
3. 実行するユーザー: 「自分」
4. アクセスできるユーザー: 「全員」
5. デプロイして発行されたURL(`https://script.google.com/macros/s/.../exec`)を控えておく

コードを更新した場合は、既存のデプロイを「編集」して新しいバージョンで
更新してください(URLは変わりません)。

### 3.3 GitHub Pagesで画面(index.html)を公開する

1. このリポジトリの GitHub ページで [Settings] タブを開く
2. 左メニューの [Pages] を開く
3. 「Source」を **「Deploy from a branch」**、ブランチはこのコードがある
   ブランチ(例: `claude/line-attendance-system-o4r0kv`)、フォルダは **`/ (root)`** を選んで保存
4. 数分待つと、`https://(あなたのGitHubユーザー名).github.io/kintai-system/` のような
   URLが発行されます(Pages画面上部に表示されます)
5. GitHub上で `index.html` を開いて鉛筆マーク(編集)をクリックし、上の方にある

   ```js
   var LIFF_ID = 'YOUR_LIFF_ID_HERE';
   var SCRIPT_URL = 'YOUR_GAS_EXEC_URL_HERE';
   ```

   の2箇所を、実際の値(後述のLIFF IDと、3.2で控えたexec URL)に書き換えてコミットする
   (書き換え後、Pagesは自動で再公開されます)

> ※ このリポジトリを非公開(Private)のままではGitHub Pagesの無料公開ができないため、
>   このリポジトリはPublic(公開)に変更する必要があります。
>   スクリプトプロパティ等の秘密情報はこのリポジトリには含まれていないため、
>   公開しても情報漏洩の心配はありません。

### 3.4 LINE Developersでの設定

> **注意**: 2019年以降、LIFFアプリは既存の **Messaging API用チャネルには直接追加できません**。
> LIFFを追加するには **「LINEログイン」チャネルを別途新規作成**し、そちらに追加する必要があります
> (Messaging API用のチャネルとは別物として、同じプロバイダーの中にもう1つ作る形になります)。

1. LINE Developersコンソールで、Messaging API用チャネルと同じプロバイダーの中に
   **新規チャネル作成 > チャネルの種類「LINEログイン」** で新しいチャネルを作成します。
2. 作成した**LINEログインチャネル**の中の「LIFF」タブ > 「追加」でLIFFアプリを追加します。
   - **Size**: Full を推奨(位置情報許可ダイアログが見やすいため)
   - **Endpoint URL**: **3.3で発行されたGitHub PagesのURL**を設定
     (GASの`.../exec`のURLではないので注意!)
   - **Scope**: `profile`, `openid` にチェック
3. 発行された **LIFF ID**(例: `1234567890-AbCdEfGh`)を控えて、
   3.3の `index.html` の `LIFF_ID` に書き込みます。
4. この**LINEログインチャネル**の「チャネル基本設定」タブにある **Channel ID** も控えておきます
   (次のスクリプトプロパティ設定で使います。Messaging API用チャネルのChannel IDとは別物です)。

### 3.5 スクリプトプロパティの設定(GAS側)

Apps Scriptエディタの [プロジェクトの設定] > [スクリプト プロパティ] で以下を設定します。

| キー | 値 |
|---|---|
| `LINE_CHANNEL_ID` | **LINEログインチャネル**(LIFFを追加した方)のChannel ID(3.4の4.) |
| `LINE_CHANNEL_SECRET` | Messaging API用チャネルのChannel Secret(現状は未使用だが将来のLINE通知拡張用に保持) |
| `LINE_CHANNEL_ACCESS_TOKEN` | Messaging API用チャネルの「チャネルアクセストークン(長期)」(9.の始業・終業リマインド機能を使う場合のみ必要) |
| `SPREADSHEET_ID` | 3.1で作成したスプレッドシートのID |
| `NOTIFY_EMAILS` | 通知先メールアドレス(複数はカンマ区切り。例: `a@example.com,b@example.com`) |

### 3.6 Geocoding.gs の User-Agent 設定

`Geocoding.gs` 内の `NOMINATIM_USER_AGENT` は、利用しているサービス
(OpenStreetMap Nominatim)の利用ポリシー上、連絡先が分かる文字列に
書き換えることを推奨します。

## 4. 動作確認の流れ

1. LINEアプリでLIFF URL(`https://liff.line.me/【LIFF ID】`)を開く
2. LINEログイン → GitHub Pagesの画面が表示され「ログイン中: 表示名」が出る
3. 「出勤」を押す → 位置情報の利用許可ダイアログが出る
   - 「許可」→ 打刻され、結果(氏名・区分・日時・簡易住所)が画面に表示される
   - 「拒否」→ 打刻はされないが、エラーメッセージと「拒否した記録の日時」が画面に表示される
4. `Records` シートに1行追加されていることを確認
   (拒否した場合は区分が「出勤(拒否)」/「退勤(拒否)」の行が追加される)
5. `NOTIFY_EMAILS` 宛にメールが届いていることを確認(拒否時はメール通知なし)

## 5. 通知方法の拡張について

`Notify.gs` の `notifyAttendance_()` が唯一の呼び出し口です。

- **宛先を増やす**: `NOTIFY_EMAILS` にカンマ区切りで追加、または
  `Employees` シートのC列に個人ごとの通知先を設定する。
- **メール以外の通知に切り替える/追加する**: `notifyViaLineMessagingApi_()`
  のような新しい関数を実装し、`notifyAttendance_()` 内から呼び出すだけで
  よい構成にしています(既存のメール通知処理には影響しません)。

## 6. セキュリティ上の注意点

- フロントエンド(LIFF画面)から送られてくる氏名やUserIDは信用せず、
  サーバー側で毎回LINEのIDトークンをLINEサーバーに問い合わせて検証しています
  (`LiffAuth.gs`)。
- 記録される氏名は、LINEの表示名(変更可能)ではなく `Employees` シートに
  事前登録した正式な氏名を使用します。マスタ未登録のアカウントからの打刻は
  拒否されます。
- 位置情報は「毎回許可ダイアログを出す」実装にしており(`maximumAge: 0`)、
  取得を拒否・失敗した場合は出退勤としては記録せず打刻を成立させません。
  ただし「誰が・いつ拒否したか」は監査目的で `Records` シートに残します
  (区分「出勤(拒否)」「退勤(拒否)」、位置情報自体は記録しません)。

## 7. 月次PDF出力(「20日締め」の勤怠帳票)

「前月21日〜当月20日」の出退勤記録を、**全社員分まとめて1つのPDF**
(社員ごとにページを分けた複数ページのPDF)として出力する機能です。
実働時間の自動計算(出勤・退勤のペアリング)は行わず、日付・区分・時刻・
簡易住所・訪問先(出勤時は「訪問先」、退勤時は「最終訪問先」)・
備考の一覧を出力します。

その場で開いて印刷する運用を想定しています。生成したPDFは
**Googleドライブに一時的に置き、15分後に自動的に削除**されます
(ポップアップ内に直接PDFを埋め込んで表示する方式も試しましたが、
Googleのダイアログのセキュリティ制限で表示できなかったため、
この方式にしています)。

### 初回だけの準備(メニューを表示させる)

このプロジェクトはスプレッドシートに直接紐付いていない(単独の)Apps Script
プロジェクトのため、`onOpen`(スプレッドシートを開いたら自動でメニューを
追加する仕組み)がそのままでは効きません。そのため、最初に1回だけ
`setupMenuTrigger` という関数を実行してトリガーを登録する必要があります。

1. Apps Scriptエディタで、関数選択のプルダウンから **`setupMenuTrigger`** を選ぶ
2. ▶実行ボタンを押す(初回は権限の承認が必要)
3. スプレッドシートのタブを開き直す(または再読み込み)
4. 上部メニューに **「勤怠帳票」** が表示されていればOK(以後この手順は不要)

### 使い方

1. 記録先のスプレッドシートを開く(ブラウザで直接開く。Apps Scriptエディタではない)
2. 上部メニューの **「勤怠帳票」** から **「月次PDFを出力」** を選ぶ
   - 初回はGoogle ドキュメント/ドライブ操作等のアクセス許可を求められるので許可する
3. 「対象の締め月」を `2026-09` のような形式で入力する
   (前月21日〜入力した月の20日、が対象期間になる)
4. 完了メッセージに表示されるリンクを開くと、社員ごとにページが
   分かれた1つのPDFが開けるので、そのまま印刷する
5. 印刷し終わったら、そのまま放っておいてよい
   (15分後に自動的にドライブから削除される。手動で先に削除しても構わない)

### 注意点

- 「(拒否)」の区分(位置情報拒否の記録)はPDFには含まれません。
- 対象期間内に打刻が1件もない社員は、PDF中に登場しません
  (全社員が0件の場合は「打刻記録が見つかりませんでした」と表示される)。
- ファイルは「勤怠PDF」フォルダに一時的に保存され、15分後に自動削除
  されます。後から見返したい場合は、15分以内にダウンロードして
  保存しておくか、その都度「月次PDFを出力」をやり直してください。
- 同じ月をもう一度出力すると、前回分は自動削除トリガーを待たず
  すぐに削除されます(常に1件だけが存在する状態になる)。

## 8. 出勤画面・退勤画面の分割(リッチメニュー2ボタン化)

`index.html` はURLの `?mode=` パラメータで表示を切り替えられるように
なっています。同じLIFF ID・同じ画面のまま、開くURLの末尾を変えるだけで
「出勤専用画面」「退勤専用画面」を用意できます(LIFFアプリを2つ作る
必要はありません)。

| URL | 表示される内容 |
|---|---|
| `https://liff.line.me/【LIFF ID】?mode=checkin` | 出勤ボタン + 「訪問先」欄のみ |
| `https://liff.line.me/【LIFF ID】?mode=checkout` | 退勤ボタン + 「最終訪問先」欄のみ |
| `https://liff.line.me/【LIFF ID】`(modeなし) | 出勤・退勤の両方(フォールバック) |

「備考」欄はどちらの画面でも共通で表示されます。

### リッチメニューを2ボタンにする

1. [LINE Official Account Manager](https://manager.line.biz/) でリッチメニューを編集
2. タップ領域を2つに分け、それぞれのアクションを「リンク」にして
   - 1つ目:`https://liff.line.me/【LIFF ID】?mode=checkin`(例:「出勤」ボタン)
   - 2つ目:`https://liff.line.me/【LIFF ID】?mode=checkout`(例:「退勤」ボタン)
3. 保存・公開

これで、リッチメニューの「出勤」を押すと出勤専用画面、「退勤」を押すと
退勤専用画面が開くようになります。

## 9. 始業・終業リマインド(打刻忘れ防止のLINE通知)

会社の勤務時間(例: 8:30〜17:15)に合わせて、平日の決まった時刻に
「まだ打刻していない社員」だけにLINEでリマインドメッセージを
自動送信する機能です。

- **8:25ごろ**: まだ「出勤」の打刻をしていない社員に、始業リマインドを送信
- **17:30ごろ**: まだ「退勤」の打刻をしていない社員に、終業リマインドを送信
- すでに打刻済みの社員には送られません
- 土曜・日曜は自動的にスキップされます
- 「会社休日」シート(A列に日付を入力するだけ)に登録した日も、あわせてスキップされます
- `Employees` シートのE列(**リマインド対象**)に **「対象」と入力した人だけ**
  送信対象になります。最初は一部の社員だけ「対象」にしておき、
  段階的に対象を広げていく、という運用ができます(3.1参照)

メッセージの文面や送信時刻は `Reminder.gs` 内の
`REMINDER_CHECKIN_MESSAGE` / `REMINDER_CHECKOUT_MESSAGE` と、
`setupReminderTriggers()` 内の `atHour()` / `nearMinute()` を書き換えれば
変更できます。

### 事前準備

1. **LINE Developersで「チャネルアクセストークン」を発行する**
   - Messaging API用チャネル(LIFFを追加した「LINEログインチャネル」とは別物)を開く
   - 「Messaging API設定」タブ内の「チャネルアクセストークン(長期)」で発行
   - 発行された値を、スクリプトプロパティ `LINE_CHANNEL_ACCESS_TOKEN` に設定する(3.5参照)
2. **「会社休日」シートを用意する**
   - `setupSheets` をもう一度実行すると自動で作成されます
   - (実行し忘れても、初回のリマインド実行時に自動で作成されます)
   - A列に、リマインドを送りたくない日付(祝日・年末年始・夏季休暇など)を1行ずつ入力しておく
   - B列は任意のメモ欄(「元日」など。空欄でもよい)
3. **トリガーを登録する(初回だけ)**
   - Apps Scriptエディタで、関数選択のプルダウンから **`setupReminderTriggers`** を選ぶ
   - ▶実行ボタンを押す(初回は権限の承認が必要)
   - これで、毎日8:25ごろ/17:30ごろに自動実行されるようになる(以後この手順は不要)

### 注意点

- LINE公式アカウントのメッセージ送信には、プランに応じた**無料通数の上限**があります。
  社員数や配信頻度によっては上限を超えて課金が発生する可能性があるため、
  LINE Official Account Managerの「利用状況」で現在のプランと消費状況を
  事前に確認しておくことをおすすめします。
- リマインドは `Employees` シートで「有効」かつ「リマインド対象」(E列が
  「対象」)になっている社員のうち、その日まだ対象区分(出勤/退勤)の
  打刻がない人にのみ送られます。「出勤(拒否)」のような位置情報拒否の
  記録は「打刻済み」として扱わないため、一度拒否した人にもリマインドが
  送られます(再度の打刻を促すため)。
- 送信時刻を変えたい場合は、`Reminder.gs` の `setupReminderTriggers()` を
  書き換えたうえで、もう一度実行してください(内部で古いトリガーを
  削除してから登録し直す作りになっているため、二重に登録される心配はありません)。
